title: "Configuration"
description: "Configure the listener, authentication, state stores, quota profiles, and provider routes."
---

llmgw reads one YAML file at startup. The decoder rejects unknown fields, multiple YAML documents, invalid values, unresolved environment variables, and references to providers or quota profiles that do not exist.

Start from `config/config.example.yaml`:

```bash
cp config/config.example.yaml config/config.yaml
go run ./cmd/llmgw -config config/config.yaml
```

## Top-level sections

| Section | Purpose |
| --- | --- |
| `server` | Listener and HTTP lifecycle timeouts |
| `auth` | Anonymous mode, static/JWT principals, ACLs, and request requirements |
| `store` | In-memory or Redis hot-path state and optional PostgreSQL limit definitions |
| `telemetry` | Service name used in logs and traces |
| `quota` | Named static quota profiles and key-to-profile assignments |
| `routes` | Public model aliases, upstream targets, operational limits, capabilities, and pricing |

## Server

```yaml
server:
  listen: ":8080"
  read_timeout: 15s
  write_timeout: 0s
  stream_write_timeout: 30s
  idle_timeout: 60s
  shutdown_timeout: 10s
```

Durations use Go duration syntax such as `500ms`, `30s`, or `10m`.

| Field | Default | Notes |
| --- | --- | --- |
| `listen` | `:8080` | TCP address passed to the Go listener |
| `read_timeout` | `15s` | Also used as the HTTP header-read timeout |
| `write_timeout` | disabled | Keep disabled for long-lived streams; per-write protection is separate |
| `stream_write_timeout` | `30s` | Downstream write-idle deadline refreshed for each response write/SSE chunk |
| `idle_timeout` | `60s` | HTTP keep-alive idle timeout |
| `shutdown_timeout` | `10s` | Graceful shutdown budget used by the command |

## Authentication

```yaml
auth:
  allow_anonymous: false
  require_user: false
  require_project: false
  max_body_bytes: 4194304
  token_envs:
    LLMGW_BEARER_TOKEN:
      id: dev
      key_id: dev-key
      providers: [openai]
      models: [gpt-4o-mini]
      permissions: [view_operations]
```

`max_body_bytes` defaults to 4 MiB and applies before route-specific body limits. If authentication is enabled, configure at least one `token_envs`/`tokens` entry or JWT verification. Anonymous mode must be explicitly enabled with `allow_anonymous: true`.

See [Authentication](/guides/authentication) for principal fields, native credential headers, and JWT configuration.

## Stores

### In-memory development mode

```yaml
store:
  mode: memory
  limit_cache_ttl: 30s
  reservation_ttl: 10m
  startup_timeout: 10s
```

Memory mode is process-local. It is suitable for development and a single replica where losing hot-path counters is acceptable. Dynamic limit definitions also disappear on restart unless PostgreSQL is configured independently.

### Shared Redis state

```yaml
store:
  mode: redis
  redis_url_env: LLMGW_REDIS_URL
  redis_namespace: llmgw-production
  reservation_ttl: 10m
  startup_timeout: 10s
```

Use a deployment-specific namespace and an environment-backed `rediss://` URL in production. `redis_url` and `redis_url_env` are mutually exclusive. The legacy `redis_addr`, `redis_password_env`, and `redis_db` form is intended for local or isolated networks and cannot be combined with a URL.

The Redis implementation requires a writable standalone primary, including `PING`, `TIME`, string/hash/sorted-set and expiry operations, plus `EVAL`/`EVALSHA`. Redis Cluster is not supported. Startup probes capabilities and fails closed.

### Durable dynamic limits

```yaml
store:
  mode: redis
  redis_url_env: LLMGW_REDIS_URL
  redis_namespace: llmgw-production
  postgres_dsn_env: LLMGW_POSTGRES_DSN
  quota_table: quota_limits
  limit_cache_ttl: 30s
```

PostgreSQL stores dynamic limit definitions written through `PUT /v1/limits`. Inference reads an in-memory snapshot; SQL is not queried per request. Redis still owns shared hot-path counters and reservations.

## Static quota profiles

```yaml
quota:
  profiles:
    standard:
      rpm: 120
      tpm: 500000
      max_parallel: 8
      daily_tokens: 2000000
      model_allowlist: [gpt-4o-mini]
      provider_allowlist: [openai]
  keys:
    customer-key-42: standard
```

The key under `quota.keys` is the resolved principal `key_id`. A dynamic limit for the same key takes precedence over the static profile.

## Routes

Every route maps a public model alias to one provider/upstream target.

```yaml
routes:
  openai-primary:
    provider: openai
    model: fast-chat
    upstream_model: gpt-4o-mini
    base_url: https://api.openai.com/v1
    api_key_env: OPENAI_API_KEY
    priority: 100
    weight: 100
    retries: 1
    timeout: 30s
    headers:
      OpenAI-Beta: responses=v1
    limits:
      rpm: 3000
      tpm: 2000000
      concurrency: 256
      provider_concurrency: 256
      max_body_bytes: 4194304
      max_response_bytes: 16777216
    circuit:
      failures: 3
      cooldown: 30s
    capabilities:
      operations: [chat.completions, responses]
      streaming: true
      tool_calling: true
      structured_output: true
      vision_input: true
      vision_input_token_surcharge: 1024
      audio: false
      reasoning: false
      max_input_tokens: 128000
      max_output_tokens: 16384
      tokenizer: o200k_base
    pricing:
      input_per_1m: 0.15
      output_per_1m: 0.60
```

### Route identity and upstream

| Field | Meaning |
| --- | --- |
| `provider` | Registered adapter: `openai`, `anthropic`, or `gemini` |
| `model` | Public alias clients send; routes sharing it form a route group |
| `upstream_model` | Provider model identifier; defaults to `model` |
| `base_url` | HTTPS upstream root; loopback/private HTTP is allowed for local compatible servers |
| `api_key_env` | Preferred environment source for the upstream key |
| `api_key` | Inline upstream key; avoid outside throwaway local configurations |
| `api_version` | Gemini API version, defaulting to the incoming version or `v1beta` |
| `headers` | Static upstream headers after validation |

`api_key` and `api_key_env` are mutually exclusive. The same rule applies to `project`/`project_env` and `location`/`location_env`. Project/location backends are not supported by the current built-in adapters.

### Ordering, weights, retries, and circuits

- Higher `priority` routes are attempted before lower priorities.
- Routes at the same priority use `weight` to choose the first candidate deterministically, then retain the remaining routes as fallbacks.
- `weight` defaults to `1` and must not exceed `1,000,000`; `timeout` defaults to `30s`.
- `retries` controls retries for retryable failures on that attempt and is capped at `10`.
- The circuit opens after `circuit.failures` (default `3`) and cools down for `circuit.cooldown` (default `30s`).
- Fallbacks never cross provider wire families because ingress pins the provider.

### Operational limits

Route `limits` protect upstream capacity per attempt. A zero value disables that guard. `provider_concurrency` must be identical on every route for a provider. Unary responses default to 16 MiB; embeddings default to 64 MiB when `max_response_bytes` is not set.

### Capabilities

Supported operation names are `chat.completions`, `responses`, `completions`, and `embeddings`. Generative routes must set a positive `max_output_tokens`. The tokenizer is required; built-in families include `cl100k_base`, `o200k_base`, `claude`, and `gemini`.

The router checks operation, streaming, tools, structured output, image/audio input, reasoning, and token caps before dispatch. When vision/audio is enabled and no surcharge is supplied, estimation defaults to 1,024 tokens per image and 8,192 tokens per audio part.

### Pricing

Token rates are expressed as currency units per one million tokens. Optional cache rates and provider-metered tools can be configured:

```yaml
pricing:
  input_per_1m: 3.00
  output_per_1m: 15.00
  cache_read_per_1m: 0.30
  cache_write_per_1m: 3.75
  provider_units:
    web_search_requests:
      micros_per_unit: 10000
      max_units_per_request: 5
```

Missing token pricing does not block requests, even under a hard spend limit, but it records zero spend and makes that ceiling incomplete. Under a hard spend limit, every enabled provider-metered tool must have a positive price and positive per-request reservation bound or the candidate is rejected.

## Reload safely

After editing the active file:

```bash
pkill -HUP -f llmgw
```

Routes, authentication, quota profiles, and request-path policy swap atomically. Invalid reloads leave the previous snapshot active. Changes to `server`, `store`, or `telemetry` are restart-only and make reload fail.

<Note>
The service resolves environment-backed fields again during reload. Ensure the process environment already contains any newly referenced variable.
</Note>
